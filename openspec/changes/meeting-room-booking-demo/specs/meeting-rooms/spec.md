# Spec Delta

## Purpose

让所有用户了解会议室的容量、设备、启用状态和当前北京时间的实际使用情况，选择会议室并联动当日查询与创建预约，同时允许模拟的超级管理员启用或停用会议室。该能力保证选择和启用状态变更不破坏已有预约及时间约束。

## ADDED Requirements

### Requirement: 展示基础会议室信息

系统 MUST 展示每个会议室的名称、容量、设备和启用状态，并至少提供 A101、A102、B201 三个会议室。

#### Scenario: 查看初始会议室
- **WHEN** 用户首次查看会议室列表
- **THEN** 系统展示 A101（4 人、电视）、A102（8 人、电视及视频会议）、B201（16 人、投影及电视及视频会议），且每个会议室均有明确的启用状态

### Requirement: 会议室选择联动卡片与预约区域

系统 MUST 允许用户点击或使用键盘选中会议室卡片，并明确显示选中状态。卡片、当日预约标题中的会议室下拉框和创建表单的会议室选择 MUST 保持同步。选择后，当日预约标题和列表 MUST 对应该会议室；管理员的启用/停用操作 MUST 不意外改变当前选择。

#### Scenario: 选择卡片后联动预约区域
- **WHEN** 用户选中 A101 卡片
- **THEN** A101 显示选中状态，标题显示“A101 当日预约”，列表只包含 A101 所选日期的记录，创建表单选择 A101

#### Scenario: 通过标题或表单切换会议室
- **WHEN** 用户在当日预约标题的下拉框或创建表单中选择 B201
- **THEN** B201 卡片显示选中状态，标题、列表和创建表单同步到 B201

#### Scenario: 停用会议室仍可选中查看
- **WHEN** 用户选中已停用的会议室
- **THEN** 系统展示该会议室的历史和当日预约，但不允许在创建表单提交该会议室的新预约

### Requirement: 按当前北京时间展示使用状态

系统 MUST 根据当前北京时间显示会议室“空闲／使用中”。仅当某条已预约记录满足开始时间 ≤ 当前时间 < 结束时间时，该会议室显示“使用中”；未来、已结束和已取消预约不使其显示使用中。该状态 MUST 独立于所选查询日期、创建时段和当前用户，并与启用状态分别展示。

#### Scenario: 到达会议开始和结束时刻
- **WHEN** A101 有一条当天 09:00～10:00 的已预约记录，当前时间依次为 08:59:59、09:00:00 和 10:00:00
- **THEN** A101 依次显示“空闲”“使用中”“空闲”，页面保持打开也会随时间更新

#### Scenario: 查询未来日期不改变当前状态
- **WHEN** 当前 A101 正在使用，用户切换到过去或未来的查询日期，并修改创建表单的会议时段或当前用户
- **THEN** A101 仍按当前真实预约显示“使用中”，未来预约不会提前使其他房间显示使用中

#### Scenario: 已取消预约不表示正在使用
- **WHEN** 当前时间位于一条已取消预约的原时段内，且没有其他有效预约覆盖当前时间
- **THEN** 该会议室显示“空闲”

#### Scenario: 停用和空闲分别表达
- **WHEN** 一个会议室已停用，且当前没有有效会议正在举行
- **THEN** 系统分别显示“停用”和“空闲”，且不允许以空闲状态为由创建预约

#### Scenario: 无法确认当前状态
- **WHEN** 当前使用状态所需的数据读取失败
- **THEN** 系统说明当前状态暂不可用，不将未知状态显示为空闲

### Requirement: 仅超级管理员可以启用或停用会议室

系统 MUST 仅允许当前模拟身份为超级管理员的用户执行启用和停用操作，并拒绝普通用户直接发起的同类操作。管理员查看启用中的会议室时 MUST 看到“停用”，查看停用中的会议室时 MUST 看到“启用”；普通用户 MUST 看不到这两个管理操作。不提供创建或编辑会议室信息的功能。

#### Scenario: 超级管理员停用会议室
- **WHEN** 当前用户为超级管理员并停用一个已启用会议室
- **THEN** 系统将该会议室改为停用，立即更新界面并禁止后续新预约

#### Scenario: 超级管理员恢复启用会议室
- **WHEN** 当前用户为超级管理员并启用一个停用中的会议室
- **THEN** 系统将会议室改为启用，立即显示“停用”操作，并允许按所有原有预约规则创建新预约

#### Scenario: 普通用户尝试管理启用状态
- **WHEN** 当前用户为普通用户并直接发起启用或停用请求
- **THEN** 系统拒绝操作，说明只有超级管理员可执行该操作，且会议室状态不变

### Requirement: 恢复启用保留预约记录

系统 MUST 在恢复启用时只改变会议室启用状态，保留全部预约及其原状态，不恢复已取消预约。原有有效预约 MUST 继续参加会议室和预约人冲突校验。

#### Scenario: 恢复启用后旧预约仍占用时段
- **WHEN** 停用会议室中有有效未来预约和已取消记录，超级管理员恢复启用该会议室
- **THEN** 两类记录状态均不变，有效预约阻止重叠预约，已取消记录不阻止预约

### Requirement: 停用保留已有预约

会议室停用后，系统 MUST 保留并允许查询其历史预约、未来预约和已取消记录。已有未来预约 MUST 继续保持原状态；已预约记录对预约人的时间冲突限制继续生效，且仍适用原有本人取消规则。

#### Scenario: 停用后查看未来预约
- **WHEN** 张三已有 A101 的未来预约，超级管理员停用 A101 后用户查询该预约日期
- **THEN** 原预约仍显示“已预约”，且系统不自动取消该预约

#### Scenario: 停用后的预约仍约束预约人
- **WHEN** A101 已停用，但张三在 A101 仍有当天 09:00～10:00 的已预约记录，张三尝试预约 B201 当天 09:30～10:30
- **THEN** 系统因预约人时间冲突拒绝新预约

#### Scenario: 本人取消停用会议室中的未来预约
- **WHEN** 预约人本人在会议开始前取消停用会议室中的预约
- **THEN** 系统允许取消并保留“已取消”记录，会议室仍为停用状态
