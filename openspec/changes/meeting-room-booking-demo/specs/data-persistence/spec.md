# Spec Delta

## Purpose

保证本机会议室预约 Demo 的基础数据和业务操作结果不会随页面刷新或应用进程退出而丢失。该能力同时约束重复启动时的初始化行为和保存失败时的一致性，使历史预约、取消记录及启用/停用状态能够持续查询和演示。

## ADDED Requirements

### Requirement: 首次运行提供可用基础数据

系统 MUST 在首次使用时提供需求规定的三个会议室、普通示例用户和一个超级管理员。初始化 MUST 不依赖公网服务，且不预置会随演示日期过期的有效预约。

#### Scenario: 首次运行即可操作
- **WHEN** 用户按 README 启动一个尚未初始化数据的本机应用
- **THEN** 可以看到 A101、A102、B201，选择普通用户或超级管理员，并使用预约与停用功能

### Requirement: 数据跨页面刷新与应用重启保留

系统 MUST 将会议室信息、启用状态和预约记录保存到页面运行时内存之外。成功创建、取消、启用和停用后的数据 MUST 在页面刷新和正常应用重启后仍然存在且内容一致，已取消预约 MUST 不被删除或恢复为已预约。

#### Scenario: 刷新保留创建与取消结果
- **WHEN** 用户成功创建两条预约并取消其中一条，然后刷新页面并查询对应日期
- **THEN** 两条记录仍在，分别显示“已预约”和“已取消”，且占用状态与这些记录一致

#### Scenario: 重启保留停用与已有预约
- **WHEN** 超级管理员停用一个已有未来预约的会议室，正常停止并重新启动应用后查询该会议室和预约
- **THEN** 会议室仍为停用，原预约内容和状态不变，创建限制和预约人冲突约束继续生效

### Requirement: 重复初始化不覆盖已有业务数据

系统 MUST 在重复启动或初始化时避免重复创建基础会议室和用户，不得通过重新填充默认数据来覆盖已有停用状态、预约内容或取消状态。

#### Scenario: 多次启动不重置状态
- **WHEN** 已有取消记录和停用会议室的应用连续启动多次
- **THEN** 基础数据不重复，既有记录数量和状态不因初始化改变

#### Scenario: 恢复启用后的状态也保留
- **WHEN** 超级管理员将停用会议室恢复启用后刷新页面并重启应用
- **THEN** 会议室仍为启用，既有预约和取消状态不变

### Requirement: 操作结果完整保存后才确认成功

系统 MUST 只在操作结果完整保存后确认创建、取消、启用或停用成功。保存失败 MUST 保留操作前的业务状态，不能出现新预约仅部分保存、取消记录丢失或启用状态操作半完成的情况。

#### Scenario: 操作保存中断
- **WHEN** 一次写入操作在确认成功之前发生存储错误
- **THEN** 系统返回可理解的失败原因，后续查询只能看到该操作之前的完整业务状态
