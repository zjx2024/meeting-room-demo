# 使用指南

先按 [README](../README.md) 安装和启动。单服务演示打开 http://127.0.0.1:8000 ；开发模式打开 http://127.0.0.1:5173 。页面显示、日期选择和预约规则均使用北京时间。

## WSL 启动

前端已构建、依赖已安装时，在 WSL 中直接执行：

```bash
cd /mnt/e/projects/meeting-room-demo
.venv/bin/python -m uvicorn app.main:create_app --factory --app-dir backend --host 127.0.0.1 --port 8000
```

这里使用项目虚拟环境的解释器，无需先激活。新开 WSL 终端后同样使用这个命令；系统的 `python3` 不会自动使用 `.venv` 中安装的 Uvicorn。首次安装和前端源码修改后的构建步骤见 README。

## 停止与重新启动

在运行服务的终端按 **Ctrl+C**，等待终端恢复命令提示符即可停止。单服务演示只需停止 Uvicorn；开发模式需在后端和 `npm run dev` 两个终端分别停止。关闭浏览器不会停止服务，停止服务不会清除数据库中的预约。

重启时重新执行启动命令，前端源码有修改时先重新构建。具体命令见 [README：停止与重新启动](../README.md#停止与重新启动)。

## 查看会议室和预约

在页面上方选择当前用户。点击会议室卡片，或切换“A101 当日预约”标题中的会议室下拉框，即可查看对应会议室；创建表单的会议室选择也会同步改变。卡片支持键盘操作，选中后有边框高亮。

“当日预约”旁的日期同时用于查询和创建预约。可以查询过去或七天以外的日期，但只能在允许的时间窗口内创建新预约。

| 看到的信息 | 含义 |
| --- | --- |
| 概况卡片“空闲/使用中” | 当前北京时间此刻是否有未取消的会议正在举行，与所选日期无关 |
| 时间轴色块 | 所选会议室在所选日期的未取消预约，位置与长度对应起止时间 |
| 时间轴留白 | 该会议室此时段没有有效预约；能否新建还要看创建表单的可用选项 |
| 明细“已预约/已取消” | 预约记录状态；会议结束后仍显示已预约，取消记录会保留 |
| 会议室“停用” | 可以查看旧记录，不能创建该会议室的新预约 |

时间轴覆盖 08:00～20:00，每格 30 分钟。下方明细保留主题、会议室、起止时间、预约人、参会人数、状态及可用的取消操作。手机显示完整时间轴和半小时分隔，文字刻度适当减少。加载、读取失败或没有选择日期时，页面会提示原因，不把未知数据显示为空闲。

## 创建预约

1. 选择当前用户、会议室和日期。首次打开会根据服务器时间准备初始日期与时段；提交前检查所选日期。
2. 填写非空会议主题和正整数参会人数，人数不能超过所选房间容量：A101 为 4 人、A102 为 8 人、B201 为 16 人。
3. 选择可用的开始和结束时间。每场 30 分钟至 4 小时，整点或半点开始/结束，在同一北京日期的 08:00～20:00 内。
4. 点击“确认预约”。成功后，时间轴新增色块，明细显示记录，可用时间选项随之更新。

开始时间必须在服务器当前时刻至 7×24 小时后之间，包含两端；只限制开始时间。当前时间不会舍入，例如 09:00:01 时不能再预约当天 09:00。

灰色且标注“不可用”的选项不能选择。系统同时考虑该房间已有的有效预约，以及当前用户在其他会议室的有效预约。开始选项需至少留出 30 分钟；结束选项检查整个会议区间，不能跨过中间已被占用的时段。修改开始时间时，结束时间默认设为下一个半小时。

例如 A101 已预约 09:00～10:00，另一用户可以选择 08:30～09:00 或从 10:00 开始，但不能选择 08:30～10:30。取消原预约后，对应时间会重新释放。

## 取消与会议室管理

只有预约人本人，且在会议开始前，才能在明细中看到并使用“取消”。到达开始时刻后就不能取消；超级管理员也不能取消别人的预约。取消后色块消失，明细保留为“已取消”，会议室和预约人的时间占用同时释放。

切换到超级管理员后，概况卡片会显示“停用”或“启用”。管理操作不会切换当前选中的会议室，也不会修改已有预约；停用房间的未来有效预约继续占用预约人的时间，仍可由本人按原规则取消。查看停用房间可点击卡片或使用当日预约标题下拉框，创建表单中的停用房间选项不可选。

## 演示流程

建议选择明天和一段空闲时间，已有记录会保留，不会随应用重启清空。需要独立演示数据时，在启动后端前按 README 设置 `MEETING_ROOM_DB_PATH`。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 张三选择 A101 和明天，在一个空闲时段创建 4 人会议 | 时间轴出现按时长占位的色块，明细显示“已预约” |
| 2 | 点击 B201 卡片，再用当日预约标题切回 A101 | 卡片、标题和创建表单同步，时间轴与明细仅显示所选房间 |
| 3 | 切换李四，在 A101 查看刚预约的时段 | 对应开始选项及会跨越该预约的结束选项不可选 |
| 4 | 切回张三，选择其他会议室 | 本人在 A101 已有会议的时段仍不可选，其他房间时间轴不会因此出现 A101 的色块 |
| 5 | 在 A101 另选可用时段，输入 5 人提交 | 页面提示最多容纳 4 人，保留输入，不新增记录 |
| 6 | 张三回到原预约明细并取消 | 色块释放，明细仍显示原记录和“已取消”，时间选项重新可用 |
| 7 | 创建一条未来预约后切换超级管理员，停用该房间 | 旧预约保留，仍能查询，新建被禁止，卡片操作变为“启用” |
| 8 | 管理员恢复启用，再按规则创建预约 | 卡片操作变为“停用”，新预约可以成功，旧记录状态不变 |
| 9 | 刷新页面，或正常停止/重启后端，再选择原日期和会议室 | 已预约、已取消记录和会议室启用状态均保留 |

演示未来预约时，概况卡片仍按当前真实时间显示空闲/使用中，未来会议不会提前显示为使用中。

### 并发冲突弹窗

用两个并排、保持可见的浏览器窗口演示，选择不同用户、相同房间、相同未来日期及同一可用时段，并先填好表单。第一个窗口提交成功后，在第二个窗口尚未自动刷新时提交。

如果第二次提交到达服务端时该时段已被占用，会弹出“A101 在 09:00～10:00 已被预约”等提示，不显示原预约人姓名。按“知道了”或 Esc 关闭，原输入保留，数据重新读取，占用选项随之禁用，可调整会议室或时间继续操作。其他输入错误显示在页面提示中。

如果第二个窗口已经刷新，占用选项会直接禁用，此时不会发出冲突请求或弹窗，属于预期行为。页面每 30 秒、重新可见及本页成功操作后刷新预约；服务端会在每次创建时再次校验。

## 常见问题

| 现象 | 说明与处理 |
| --- | --- |
| WSL 提示 `python` 找不到，或 `python3` 提示 `No module named uvicorn` | 在项目根目录使用 `.venv/bin/python -m uvicorn ...`；如果虚拟环境尚未创建或没有依赖，先按 README 安装 |
| 修改了前端源码，8000 页面没有变化 | 在 `frontend` 执行 `npm run build` 后刷新；开发时可打开 5173 查看 Vite 更新 |
| 8000 提示先构建前端 | 按 README 执行前端安装、类型检查和构建；API 可独立使用 |
| 时间轴有留白，但对应时间不可选 | 检查本人在其他房间是否有会议、开始是否已过去或超过七天、房间是否停用，以及所选开始/结束是否满足时长规则 |
| 创建按钮不可用 | 检查日期、房间和所选时段；预约读取失败时先恢复数据读取再继续 |
| 没有取消按钮 | 检查当前用户是否为预约人、记录是否已取消、会议是否已经开始 |
| 已取消记录还在明细中 | 这是预期行为，用于查询历史；它不会占用时间轴或阻止重新预约 |
| 停用会议室显示空闲 | 启用状态和当前使用状态分别展示，停用仍不能创建新预约 |
| 刷新后用户或选房改变 | 当前界面选择不作为持久化偏好保存，重新选择用户、日期和会议室即可查询已有数据 |

安装、端口、测试命令和数据库路径见 [README](../README.md)，实际验收报告见 [验证记录](verification.md)。
