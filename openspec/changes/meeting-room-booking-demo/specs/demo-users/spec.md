# Spec Delta

## Purpose

为本机 Demo 提供无需完整登录认证的当前用户选择方式，使预约归属、本人取消和超级管理员启用/停用操作都具有清晰身份依据。该能力仅模拟身份和角色，不扩展为账号注册、登录认证或用户管理系统。

## ADDED Requirements

### Requirement: 使用选择器模拟当前用户

系统 MUST 提供预置用户选择器，至少包含张三、李四、王五三个普通用户和一个超级管理员。切换选择器后，后续操作 MUST 使用新选择的身份；无需注册或登录。

#### Scenario: 切换用户后操作身份改变
- **WHEN** 用户从张三切换到李四并提交一个合法预约
- **THEN** 新预约归属于李四，张三已有的预约归属不变

#### Scenario: 选择超级管理员
- **WHEN** 用户在选择器中选择超级管理员
- **THEN** 系统允许该身份执行会议室启用和停用操作，且不要求独立登录

### Requirement: 预约人固定为当前用户

创建预约时，系统 MUST 将预约人固定为当前有效用户，不提供代预约入口，也不得接受与当前身份不同的预约人。缺少有效身份时 MUST 拒绝写入并说明需要选择用户。

#### Scenario: 创建表单展示当前预约人
- **WHEN** 当前用户为张三并打开预约表单
- **THEN** 预约人显示为张三且不可另选其他人

#### Scenario: 请求试图替他人预约
- **WHEN** 当前身份为张三的请求试图指定李四为预约人
- **THEN** 系统拒绝身份不一致的请求，且不产生属于李四的预约

#### Scenario: 未选择有效用户
- **WHEN** 创建、取消、启用或停用请求没有有效的当前用户身份
- **THEN** 系统拒绝操作并提示选择有效用户，不改变业务数据

### Requirement: 角色不扩大取消权限

系统 MUST 根据当前用户判断本人取消权限和管理员启用/停用权限。超级管理员角色 MUST 不获得取消他人预约的额外权限；切换身份 MUST 不修改既有预约的所有者。

#### Scenario: 超级管理员不能取消他人预约
- **WHEN** 当前用户是超级管理员，尝试取消张三尚未开始的预约
- **THEN** 系统拒绝操作并说明只能取消自己的预约，原预约保持“已预约”

#### Scenario: 普通用户本人可以按规则取消
- **WHEN** 当前用户为张三，并在开始时间之前取消张三自己的已预约记录
- **THEN** 系统允许取消，且不要求管理员身份
